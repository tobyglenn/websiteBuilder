[02:00] Qwen 3.6 27B at 80 Tokens/Second on Mixed RTX 5080 and RTX 3090 Setup

A blog post on imil.net walks through a heterogeneous dual-GPU configuration: an RTX 5080 paired with an RTX 3090, both consumer cards from different generations, running a 27-billion-parameter Qwen model at Q8 quantization. The headline result is sustained generation throughput above 80 tokens per second. The Hacker News thread around the post reached 252 points, with commenters comparing numbers against their own local setups and probing the inference runtime choice.

The technical mechanism centers on layer splitting across the two GPUs. The combined VRAM holds the full Q8 model plus KV cache headroom, so no offloading to system RAM is required during inference. The runtime is configured to assign a contiguous block of transformer layers to each card, which avoids hot-swapping weights mid-pass. The bottleneck shifts to PCIe bandwidth between the two devices, since activation tensors for any layer that crosses the boundary must travel over the bus. Q8 quantization is what makes the arrangement viable: it shrinks the model enough to fit comfortably on two non-flagship cards while keeping per-token decode work manageable.

Latency-wise, 80 tok/s at Q8 sits well within the comfort zone for interactive chat and inline code completion against a 27B model. The trade-off is the quantization step itself, which slightly degrades reasoning and code quality compared to FP16 or BF16 baselines. Inference setup details — the specific backend, sampling config, and prompt-processing throughput — are in the blog post itself, which is worth a read if you're building a local inference rig from mismatched parts.

What to watch next: whether newer llama.cpp or vLLM releases further optimize mixed-vendor and mixed-generation tensor parallelism, and whether consumer-tier NVLink changes the bandwidth bottleneck for setups like this one.

[00:00] Qwen 3.6 27B at 80 Tokens/Second on Mixed RTX 5080 and RTX 3090 Setup

Alloy A detailed technical post on imil.net has captured the attention of the local LLM community, documenting a heterogeneous dual-GPU configuration that achieves enterprise-grade throughput on consumer hardware. The setup pairs an RTX 5080 with an RTX 3090 to run Qwen 3.6 27B at 8-bit quantization, sustaining over 80 tokens per second. This is a significant milestone because it demonstrates that builders don't need a unified high-VRAM accelerator like an A100 or H100 to achieve high-speed inference on models in the 30-billion-parameter class.

Nova The technical mechanism here is a clean tensor-parallel layer split. In this configuration, the transformer layers of the Qwen model are distributed across the available VRAM of both cards. Because the 5080 and 3090 combined offer a substantial memory pool, the entire Q8 quantized payload fits comfortably with enough headroom for a large KV cache. The inference runs on a backend similar to llama.cpp, where the runtime assigns a contiguous block of layers to each GPU. This avoids the need to swap weights in and out of system memory, which is the primary killer of local inference performance.

Alloy The bottleneck in a setup like this is typically the PCIe host bandwidth. Unlike enterprise setups that use NVLink or Infinity Fabric for high-speed inter-GPU communication, these consumer cards have to send activation tensors across the motherboard's PCIe bus. Every time the model finish processing the layers on the first card, the resulting data must be transferred to the second card to continue the pass. However, at 8-bit quantization, the size of those activation tensors is small enough that the PCIe overhead doesn't prevent the system from hitting that 80-token-per-second mark. For context, most human readers consume text at about 5 to 10 tokens per second, so this setup provides an experience that is effectively instantaneous for interactive use.

Nova Builders are looking at this as a blueprint for repurposing older hardware. The RTX 3090 remains a favorite in the community because of its 24 gigabytes of VRAM, and pairing it with a newer, faster card like the 5080 allows the system to benefit from the newer card's compute power while utilizing the older card's capacity. The Q8 quantization is the key trade-off; while it significantly reduces the memory footprint and increases speed, there is a measurable, though often slight, impact on reasoning quality compared to the full 16-bit precision model. For agentic workflows where speed and cost-per-token are the primary constraints, this is a trade-off many are willing to make.

Alloy The broader implication is the continued viability of the "mismatched" rig. We are seeing more sophisticated logic in model runners to handle these heterogeneous pools. The observation is that as long as you can fit the model across the combined VRAM, the specific generation of the silicon matters less than the total memory bandwidth and the PCIe version of the slot it's sitting in. This validates a path for developers to build powerful local agent stacks without a five-figure hardware investment. [PAUSE]

By routing the "low-level" work to a cheaper model and keeping the "high-level" model's context window as small as possible, you can dramatically scale the complexity of the tasks your agent can handle without blowing your budget.

Alloy For builders, this validates a pattern where the orchestrator never holds the full source payload in its active session. Instead, you maintain a "state summary" that the orchestrator uses to navigate the project. This is a much more scalable way to build agents for large repositories. If you are running an agent loop that is currently burning thousands of dollars a month in token costs, implementing a planner-builder split like this is the most immediate way to improve your efficiency.

Nova There is a secondary benefit that often gets missed in cost-focused writeups. When the reviewer only ever sees a structured summary, the same summary structure can be cached at the inference layer. If your summarization function is deterministic on the same input, you can hit the provider's prompt-cache layer and skip the reviewer's prefill cost on every subsequent pass. That is where the real savings stack up: not just "smaller prompts," but "smaller prompts that are also cacheable." A planner that never re-reads raw source ends up looking like a sequence of cheap continuation calls, which is a very different cost profile from a reviewer that re-processes the whole diff on every iteration.

Alloy The other architectural lesson is the boundary between the two agents. Architect-loop draws that boundary at "structured review artifacts" — test results, lint output, a diff summary, and a list of the next three actions. That is a very clean contract. If you are building your own multi-agent setup, the temptation is to pass the builder's full output through to the planner and let the planner figure out what to do with it. That coupling is what makes reviewer models expensive. A planner that only ever consumes a stable, structured envelope will be much cheaper to operate and much easier to swap when you want to upgrade one of the two models independently.

Nova The 80% reduction figure is the project's own measurement, so the right read is "this is a real and reproducible pattern in the open codebase," not "every reviewer model will show the same number." The shape of the savings depends on how chatty your builder is and how much of the source it churns through per pass. But the qualitative claim — that selective context plus a structured planner-builder boundary is cheaper than a single agent doing both jobs — holds up across the broader multi-agent literature, and architect-loop is the cleanest public demonstration of it this cycle. Nova Developer Koen van Gilst has published "Shepherd's Dog," a fully playable web-based game that was authored almost entirely by Claude using a custom agentic harness. Alloy The harness used for this project—also called Fable, though distinct from the model name—is an orchestration layer that allows Claude to iterate on a complete codebase. The agent can create new files, modify existing ones, and run the build process to see if the game actually works. This is how the project was able to move from a high-level concept to a finished, playable build in a single focused session.

Nova What's particularly interesting about "Shepherd's Dog" is that it demonstrates the "upper limit" of what current-generation models can handle in terms of architectural complexity. The game has state management, collision detection, and a rendering loop—all things that require a cohesive understanding of how the different parts of the code interact. Alloy This project is also a great example of the "agent-driven authoring" trend. For anyone wondering whether these tools are ready for "production-grade" application development, "Shepherd's Dog" provides a very convincing piece of evidence. The harness and the source for the project are both available for other builders to study and adapt.

Nova The reproducibility caveat is real and worth flagging. Because the model is non-deterministic at temperature settings used for creative work, the exact game Koen shipped is not necessarily the game a second developer will get from the same prompt sequence. The architectural shape will look similar, but the specific implementation details — the art style, the collision tuning, the level layout — will diverge. For teams thinking about adopting a Fable-style harness for their own product, the takeaway is that the harness gives you a stable authoring loop, but you still need a deterministic layer somewhere downstream if you want reproducible builds. Alloy And that is the part we think is most underdiscussed: the harness is not just a "let the model write code" wrapper.
