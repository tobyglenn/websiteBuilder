Episode Title

OpenClaw Gets a Brain Transplant, Glasswing, Giant Brains, and Cloned Writers

Tagline

OpenClaw 2026.4.8 ships a unified inference layer, session checkpointing, and a fully restored memory stack — then Anthropic calls in the tech giants to fight AI vulnerabilities with AI, a new paper trains 120B parameters on one GPU, and a fingerprinting study reveals your writing AI is probably a Claude clone.

Story Slate

  1. OpenClaw 2026.4.8 — The Release That Changes How It All Works The anchor story. Six major subsystems land in one release: a new infer hub CLI that unifies routing across providers, a media generation auto-fallback system that eliminates an entire class of failures, a sessions branch-and-restore UI that creates checkpoints before context compaction, full restoration of the memory and wiki stack with structured claims, evidence, contradiction clustering and freshness-weighted search, a webhook ingress plugin for external automation, and a pluggable compaction provider registry so you can route summarisation to a faster/cheaper model. Plus Google Gemma 4 support, Claude CLI restored as the preferred local Anthropic path, Ollama vision models natively, and a batch of security-relevant fixes covering host exec sanitisation, allowlist authorization, and multi-channel gateway startup errors.

  2. Project Glasswing: The Cyber Defense Coalition Anthropic assembled basically every major tech and finance company to unleash Claude Mythos Preview — an unreleased frontier model that found thousands of zero-days including a 27-year-old OpenBSD bug and a 16-year-old FFmpeg flaw. The pitch: AI breaks things faster than humans can fix them, so fight AI with AI. $100M in credits, $4M to open-source security orgs. Great premise, worth discussing what "coalition" really means when Anthropic is holding the keys.

  3. MegaTrain: 100B+ Parameters, One GPU A new paper drops a technique that stores model weights and optimizer state in host CPU memory and treats GPUs as disposable compute units. Result: 120B parameter training on a single H200 with 1.5TB RAM, 1.84x faster throughput than DeepSpeed ZeRO-3 on 14B models. This is a big deal for anyone who thought you needed a full cluster to train frontier-scale models.

  4. Your AI Writer Is Probably a Claude Clone A fingerprinting study of 178 AI models found 9 clone clusters with >90% style similarity. Most striking: Gemini 2.5 Flash Lite writes 78% like Claude 3 Opus — at 185x lower cost. The implications for "AI slop" and how model convergence happens even across totally different training runs are worth unpacking.

  5. LLM Plays Shoot-'Em-Up on a 40-Year-Old 8-bit Machine GPT-4o connected to a Commander X16 emulator via text summaries of game state — no pixels, no audio. It developed strategies, kept notes between turns, and found an exploit in the built-in AI. A fun, low-budget demo that shows structured reasoning can emerge from surprisingly minimal input.

Nova Let us move to Story Two.

Nova Anthropic announced Project Glasswing today, and I want to start with the announcement itself and then get into the questions it raises, because it is one of those announcements that is simultaneously impressive and a little unsettling.

Nova The coalition Anthropic assembled is remarkable in its scope. Amazon, Apple, Broadcom, Cisco, CrowdStrike, Google, JPMorgan Chase, Microsoft, NVIDIA, Palo Alto Networks. This is not a list of AI startups or research institutions. This is a list of the companies that collectively represent the infrastructure, financial system, and security posture of the global internet. When Anthropic puts out a press release and that is the partner list, the ambition of what they are describing is different from what we normally see in AI safety or security announcements.

Alloy The press release framing is collective defense. The language is about collaboration, shared mission, and applying AI to the problem of AI-generated vulnerabilities at scale. And I think the intent is real — the resources being committed are real, the participating security teams are real, and the problem they are describing is real. But I also think it is worth being precise about what the structural arrangement actually is before we accept the framing at face value.

Nova The centerpiece is a model called Claude Mythos Preview. Anthropic describes it as a frontier model positioned specifically for offensive security research. It is not publicly available. It is not open source. Access is controlled by Anthropic and provided to the coalition partners under terms they have negotiated. The capability numbers are genuinely striking. Mythos Preview scored 83.1% on the CyberGym benchmark. That is a security evaluation benchmark. For reference, Anthropic's own Opus 4.6 — their previous top-of-the-line model — scored 66.6%. The gap between the two is not small. This is a specialized, unreleased model that outperforms the best publicly available model by a very significant margin on the exact task they are deploying it for.

Nova And the results they have produced are not cherry-picked. They say the model found thousands of zero-day vulnerabilities during testing. Thousands. In existing, actively maintained codebases. Among the specific findings they cited: a vulnerability in OpenBSD that has been present since 1998 — 27 years — and a flaw in FFmpeg that has been sitting in that project for 16 years. These are not easy finds. These are vulnerabilities that have survived decades of code review, security auditing, and normal development cycles. The model found them in the course of automated scanning.

Alloy And it found them fast, presumably. They do not give specific timelines, but the implication is that this was done in a research evaluation period, not over years of manual effort. A 27-year-old bug in a widely used open-source operating system, found by a model reading code. That is the capability level we are talking about.

Nova Anthropic is backing the coalition with real resources. 100 million dollars in compute credits for security research, and 4 million in direct funding to open-source security organizations. That is not a symbolic commitment — that is real money that will fund actual security research work.

Alloy But here is the question I keep coming back to. What does coalition mean when one party controls the weapon? Mythos Preview is not open. It is not publicly available. The partners get access under terms that Anthropic sets. Anthropic decides who can use it, for what, and under what conditions. So what we are actually seeing is a group of very powerful organizations becoming dependent on Anthropic's API for their security research posture. That is a different structural relationship than a genuine multilateral coalition where everyone has equal access and equal voice.

Nova And that matters for a few reasons. The first is leverage. If a significant portion of global critical infrastructure security research is running through Anthropic's model, that is an extraordinary position. JPMorgan Chase, Apple, Amazon — these are organizations whose security posture has material impact on global financial systems and supply chains. When Anthropic sets terms for that relationship, they are sitting across the table from some of the most powerful institutions in the world, and those institutions have already invested in building workflows and institutional knowledge around the model. That is a deep relationship that is not trivial to walk away from.

Nova The second question is what happens when the model finds something in a partner's code. Not a competitor's code — a partner's code. OpenBSD and FFmpeg are the examples Anthropic cited for what the model can find. But what about when it finds something in Google's code, or Microsoft's code, or JPMorgan's code? What is the disclosure timeline? Who controls that? Is there a window before the partner is notified? Is the disclosure automatic? These are not academic questions. The answers to those questions determine whether this is a genuine security coalition or a security intelligence relationship.

Alloy And the third question is what this means for the broader security ecosystem. If the dominant model for security research is a proprietary Anthropic model that only coalition partners have access to, what happens to the open-source security tooling ecosystem? Researchers who do not have access to Mythos Preview are working with significantly less capable tools. The gap between what Anthropic's partners can find and what everyone else can find widens. That has implications for the overall security of the internet that go beyond the coalition itself.

Nova I want to be clear that I am not saying the announcement is bad or that the intent is wrong. I think the problem they are describing is real. I think AI-generated vulnerabilities at scale is a legitimate and growing concern. I think the capability they are demonstrating is remarkable. And I think having actual security practitioners from CrowdStrike, Palo Alto Networks, and Cisco involved in the feedback loop probably makes the model meaningfully better than it would be otherwise. The cooperation is real on some level.

Nova But the structural arrangement — one company controls the weapon, everyone else shows up as a customer or a partner on terms that company sets — is not the same thing as collective defense. And I think it is worth being clear about the difference, because the framing of "coalition" is doing a lot of work in the announcement that the actual arrangement might not fully support.

Nova Let us move to Story Three.

Nova There is a new paper on arXiv called MegaTrain, and I want to just state the core claim before we unpack it. MegaTrain can train models with over 100 billion parameters on a single GPU. One GPU. Not a cluster. Not a specialized machine. One GPU.

Alloy I want to make sure people understand why that sounds impossible and then understand why it is actually working. The traditional constraint on training large models has been VRAM. GPU memory holds the model weights, the optimizer state, the gradients, and the activations for each training step. At 100 billion parameters, the numbers are staggering. Even with 16-bit precision, you are talking about 200 gigabytes just for the weights. The optimizer state for a 100-billion-parameter model trained with Adam is roughly three times the model size — 600 gigabytes. No current GPU has that much VRAM. The standard solution is model parallelism: shard the model across multiple GPUs, pipeline the computation, and accept the communication overhead.

Nova MegaTrain takes a different approach. Instead of distributing the model across GPUs, it keeps the model weights and optimizer state in host CPU memory and treats the GPUs as disposable compute units. When a GPU needs to do a piece of computation, it streams the relevant weights from CPU memory, performs the arithmetic, and streams the results back. The GPU is not storing the model — it is just doing the math on data it fetches on demand.

Alloy And the reason this is becoming viable now is that GPU compute density has been advancing faster than GPU memory capacity. Bandwidth between CPU and GPU has been improving significantly with newer architectures like the GH200, which combines CPU and GPU memory in a unified pool. The H200 has 1.5 terabytes of CPU memory available for the system, and the bandwidth between CPU and GPU on that platform is high enough that streaming weights in and out is not as punishing as it would have been on older hardware.

Nova They demonstrate training a 120-billion-parameter model on a single H200 with 1.5 terabytes of system RAM. That is a lot of RAM and it is not cheap, but a single H200 is a commercially available machine. You do not need a data center. You do not need a cluster. You need one very expensive server. And that is a meaningful change in the accessibility of frontier training.

Alloy For smaller models, the numbers are actually impressive in terms of throughput. MegaTrain achieves 1.84 times faster training than DeepSpeed ZeRO-3 on a 14-billion-parameter model. ZeRO-3 is one of the most widely used approaches for distributed training of large models. Beating it by nearly 2x on a single machine on a smaller scale model suggests the streaming architecture has genuine efficiency advantages, not just memory advantages.

Nova But the number that I keep thinking about is the 7-billion-parameter model trained with 512,000 tokens of context on a single GH200. 512,000 tokens. That is a frontier-scale context window. Gemini 1.5 Pro launched with a 1-million-token context window and it was considered a landmark achievement. MegaTrain is demonstrating that you can train a model with half a million tokens of context on one chip. One GH200. No cluster. No InfiniBand networking. No special interconnect. One chip.

Alloy The implication is a significant democratization of frontier research capability. A university lab, an independent researcher, a small company — they can now run experiments that previously required a cluster of H100s. The cost curve for this kind of training is changing. It is not free, and it is not trivial, but the gap between what you can do on a research budget and what you can do at a major lab is getting meaningfully smaller.

Nova And it has implications for the concentration of AI capability more broadly. If training large models becomes cheap enough to do on premise without specialized infrastructure, the moat that large labs have is not gone, but it shrinks. The advantage shifts from "you have access to training infrastructure nobody else can afford" to "you have access to more training infrastructure than anyone else." Those are different competitive positions.

Nova The paper is at arxiv dot org slash abs slash 2604.05091. The technical details of how they manage weight streaming, gradient computation across the CPU-GPU boundary, and optimizer state management are non-trivial and worth reading if you are working in this space.

Nova Story Four.

Nova A fingerprinting study of 178 AI models turned up something that has been sitting in the back of my mind since I first saw it. The researchers found nine distinct clone clusters — groups of models that showed over 90% style similarity to each other despite being trained completely independently. Not similar content. Identical style fingerprints. Nine separate groups of models that arrived at the same writing style through independent training runs.

Alloy The headliner is Gemini 2.5 Flash Lite, which is Google's budget model — the lightweight, low-cost version of their flagship. According to the study, Gemini 2.5 Flash Lite writes with 78% style similarity to Claude 3 Opus. And it is 185 times cheaper to run. Let me just sit with that number. 185 times cheaper. You can get a model that writes in a way that is 78% similar to the best thing Anthropic makes, at a fraction of the cost, from Google.

Nova The two explanations the researchers propose are both probably true to some degree, and they lead to very different conclusions.

Nova Explanation one is model convergence. Given enough scale and similar training approaches, independent training runs naturally fall into the same patterns. Everyone is using similar pretraining data — the same books, the same code, the same articles. Everyone is using similar human feedback signals — the same preference datasets, the same raters, the same notion of what good writing looks like. If everyone is optimizing toward the same target, they eventually arrive at the same basin of attraction, even from completely different starting points. The style that humans consistently rate as helpful and trustworthy might just be narrower than the field realized.

Nova Explanation two is that Claude's style is a strong RLHF attractor. Claude's conversational DNA — balanced, thoughtful, appropriately hedged, readable, structured — is not an accident. It is the result of very deliberate, very expensive training by Anthropic. And if that specific style is what humans consistently rate as helpful and trustworthy, then every other model that wants high user satisfaction scores will be pulled toward it. Not because they are copying Claude, but because they are all discovering the same optimal response pattern, and Claude got there first and had the brand recognition to make it feel like Claude's voice was a unique identity rather than a statistical attractor.

Alloy I think the second explanation is probably more correct, and it has a specific implication that I want to be direct about. If the "personality" that AI labs spend months engineering is actually a strong RLHF attractor, then it is not a moat. It is a magnet. And once you are a strong enough attractor, everyone else gets pulled toward you whether they want to be or not. Their models converge to your style even if they never trained on your outputs.

Nova And if that is true, then any startup that is building a product and claiming their AI has a unique, differentiated voice is probably building on a foundation that is thinner than they think. If the underlying models are all converging to the same style regardless of how they were trained, then your unique AI personality is probably just a prompt template. And a prompt template is not a durable competitive advantage.

Nova The discussion thread is live on Hacker News — item 47690415. Go read it. There are some genuinely interesting takes in there from people who have thought about this from both the model development side and the product side.

Nova Story Five.

Nova A developer connected GPT-4o to a Commander X16 emulator. For those who do not know, the Commander X16 is an 8-bit home computer designed as an open-source recreation of the Commodore 64 experience. It uses a 6502 processor — the same chip family as the original C64. It runs at 8 megahertz. It has 128 kilobytes of RAM. By any modern standard, it is an artifact.

Nova The setup for this experiment was deliberately minimal. No pixel data. No audio. GPT-4o received only structured text summaries of the game state — player position, enemy positions, bullets on screen, score, lives remaining, whatever the emulator could export as plain text. The model had to play a shoot-em-up game using nothing but words.

Alloy And it worked better than you would expect. The model developed strategies over time. More interestingly, it started keeping its own notes on enemy patterns — not because anyone told it to keep notes, but because it recognized that tracking observations across turns was useful and figured out a way to do that within the constraints of the text interface. That is emergent metacognition. The model recognized a need for persistent state across interactions and invented a notational system to satisfy that need without being asked.

Nova Eventually, it found an exploit in the Commander X16's built-in AI opponent — a behavior that the original game developers had not anticipated. It was not just reacting frame by frame to what it saw. It had built a model of how the AI worked, identified a weakness in that model, and exploited it. The developer did not expect that. The model just noticed.

Alloy The interesting part is not that an LLM can play a video game. We have seen that. The interesting part is the interface constraint and what it reveals. In the real world, you do not always get pixel-level access. You get a text readout. You get an API response. You get a log file. You get a summary. The question has always been what you can accomplish with that constraint. This experiment suggests the answer is: quite a lot, including strategic reasoning that the original developers did not anticipate. And that has implications for how we think about deploying AI agents in production environments where the interface is constrained by design.
