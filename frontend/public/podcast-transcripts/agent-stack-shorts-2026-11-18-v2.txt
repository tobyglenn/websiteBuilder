GPT six point two Astra and Sol have arrived, and the most useful distinction is not simply which model is smarter. It is which one deserves the next job in your workflow.

OpenAI positions Astra for harder work across a codebase and for visual tasks. Sol is the faster everyday option. On OpenAI's FrontierCode two point zero evaluation, Sol came within half a point of Astra while costing about one fifth as much per task. That is OpenAI's reported result, not a benchmark I ran. But it gives us a practical starting point: use Sol for routine implementation and iteration, then bring Astra into difficult debugging, interacting changes, and work where a mistake would force a substantial redo.

For a website, that could mean Sol handles a focused component change while Astra evaluates a larger redesign that touches navigation, layout, and content together. For a podcast pipeline, Sol can help with a contained script fix, while Astra is the more deliberate choice for tracing a failure across generation, staging, and release. Those are workflow choices, not a claim that either model will automatically validate every change it makes.

Both models are available to Plus and Pro users in ChatGPT Work and Codex. On the hundred dollar Pro plan, the standard models are the relevant addition. The separately named Ultrafast mode is listed for both models on Pro five hundred, and for Sol on Pro two hundred. API use is billed separately from the ChatGPT subscription, so choosing a model through an API key is a different cost decision from selecting it inside an included app.

The second story is Antigravity's remote Linux support. Version two point thirty-three can install its remote server over OpenSSH and run projects, Git worktrees, agents, and terminals on that host. The interface stays on your computer, but the actual repository work happens remotely. That is a concrete fit for editing a DGX-hosted project from a Mac without maintaining a second working copy just to drive the editor.

The connection starts through SSH Host in the sidebar and can use existing OpenSSH configuration. Remote work can continue after the editor window closes. That makes the distinction between closing an interface and stopping a job much clearer: a build or agent session lives on the machine doing the work. It also puts the relevant dependencies and files in the same environment as the command being run, instead of assuming that a local result represents the remote setup.

Antigravity also raises audio and video previews from twenty megabytes to two hundred megabytes, useful for reviewing larger podcast drafts in the editor. Separately, its model list schedules Sonnet four point six, Opus four point six, and GPT O S S one twenty for removal on November eighteenth. A workflow pinned to one of those choices needs a replacement from the current picker.

OpenCode has two changes that matter for longer agent sessions. Version two point three point one moves a shell command into the background when its timeout expires rather than killing it. A slow build or test run can therefore continue instead of losing the work at an arbitrary waiting limit. The practical payoff is especially clear when a project has a long verification step: the agent can preserve that running process and come back to its result.

The same release adds Astra and Sol to the model picker for ChatGPT sign-in. Version two point three point two then fixes repeated uncached system prompts for those models. OpenCode says the prompt can be cached from the second step. In a multi-step API session, reusing the common prompt can reduce repeated input cost. That is distinct from promising a particular reduction in subscription usage. Background compaction is another part of the long-session improvements, helping ongoing work manage its accumulated context.

Finally, Claude Code two point one point three two seven addresses failures that are easy to miss when agents run unattended. It fixes a Remote Control issue that could delete Git-ignored files in an active worktree, and a headless-resume problem that could lose messages after a kill and retry. Ignored does not mean disposable: generated assets, local outputs, and other useful working material may all sit outside tracked source files.

The release also makes diagnosis more direct. Slash status surfaces broken skills and agents, while slash config identifies configuration overrides. MCP connection retries can continue for roughly a day. Together, those changes help separate a temporarily unavailable integration from a broken configuration, and make it easier to understand why a resumed job is behaving differently from the original session.
