अपना पहला Node.js REST API बनाना: शुरुआती लोगों के लिए एक पूर्ण गाइड

Node.js और Restify का उपयोग करके एक कार्यात्मक REST API सर्वर बनाना सीखें, इंस्टॉलेशन से लेकर वास्तविक उदाहरणों के साथ GET और POST अनुरोधों को संभालने तक।

Toby 29 मार्च 2026
𝕏fin

परिचय: बैकएंड डेवलपमेंट के लिए Node.js क्यों?

अगर आप scheduler node server प्रोजेक्ट के साथ आगे बढ़ रहे हैं, तो आप पहले से जानते हैं कि Node.js सर्वर-साइड एप्लिकेशन बनाने के लिए एक अविश्वसनीय रूप से शक्तिशाली प्लेटफ़ॉर्म है। लेकिन अगर आप अभी शुरुआत कर रहे हैं, तो आप सोच रहे होंगे: Node.js क्यों? पारंपरिक सर्वर-साइड भाषाओं के साथ क्यों न रहें?

इसका उत्तर Node.js के event-driven, non-blocking I/O मॉडल में निहित है, जो इसे concurrent connections को संभालने के लिए अविश्वसनीय रूप से कुशल बनाता है—यह उन आधुनिक वेब एप्लिकेशन के लिए बिल्कुल उपयुक्त है जिन्हें real-time data, APIs, और microservices को संभालने की आवश्यकता होती है।

इस ट्यूटोरियल में, हम Node.js और Restify फ्रेमवर्क का उपयोग करके आपका पहला REST API server बनाने की प्रक्रिया से गुजरेंगे। अंत तक, आपके पास एक कार्यशील server होगा जो POST requests स्वीकार कर सकता है, data store कर सकता है, और GET requests के माध्यम से उसे वापस serve कर सकता है।

चरण 1: Node.js और NPM इंस्टॉल करना

इससे पहले कि हम कोई कोड लिखें, हमें अपना development environment सेट करना होगा। प्रक्रिया सीधी है:

macOS पर (अनुशंसित तरीका)

अगर आप Mac पर हैं, तो मैं Homebrew का उपयोग करने की अत्यधिक सिफारिश करता हूँ—यह Node.js installations को manage करने का सबसे आसान तरीका है:

brew install node

यह एकल कमांड Node.js और NPM (Node Package Manager) दोनों को install कर देगी, जिनकी हमें frameworks और packages install करने के लिए आवश्यकता होगी।

सत्यापन

Installation के बाद, सत्यापित करें कि सब कुछ काम कर रहा है:

node --version
npm --version

आपको दोनों के लिए version numbers दिखने चाहिए, जो पुष्टि करते हैं कि आपका installation सफल रहा।

चरण 2: फ्रेमवर्क चयन को समझना

Node.js built-in HTTP server क्षमताओं के साथ आता है, लेकिन raw HTTP server कोड लिखना जल्दी जटिल हो सकता है। यहीं पर Restify और Express जैसे frameworks काम आते हैं।

Restify बनाम Express: अंतर क्या है?

  • Express एक full-featured web framework है जो routing से लेकर templating तक सब कुछ handle कर सकता है, जो इसे पूर्ण web applications बनाने के लिए आदर्श बनाता है।
  • Restify एक leaner framework है जो विशेष रूप से RESTful APIs बनाने के लिए डिज़ाइन किया गया है। यह essentials पर केंद्रित है: endpoints, HTTP methods, और JSON handling।

हमारे scheduler प्रोजेक्ट के लिए, हम Restify का उपयोग कर रहे हैं क्योंकि हमें full web server के overhead के बिना एक clean API endpoint चाहिए।

चरण 3: अपना पहला Server बनाना

आइए Restify का उपयोग करके एक बुनियादी "Hello World" server से शुरू करें:

var restify = require('restify');

var server = restify.createServer({
    name: 'scheduler-api'
});

server.get('/test', function(req, res, next) {
    res.send('Test endpoint working!');
    next();
});

server.listen(8080, function() {
    console.log('Server listening on port 8080');
});

इसे index.js के रूप में सेव करें और node index.js के साथ चलाएँ। फिर अपने ब्राउज़र में http://localhost:8080/test पर जाएँ—आपको अपना संदेश दिखना चाहिए!

चरण 4: GET बनाम POST को समझना

इससे पहले कि हम POST अनुरोधों में गहराई से जाएँ, आइए HTTP विधियों के बीच का अंतर स्पष्ट करें:

GET अनुरोध

GET का उपयोग सर्वर से डेटा प्राप्त करने के लिए किया जाता है। आप एक URL भेजते हैं (वैकल्पिक रूप से क्वेरी पैरामीटर के साथ), और सर्वर डेटा के साथ प्रतिक्रिया देता है। यह वही है जो हमने अभी अपने /test एंडपॉइंट के साथ किया था।

POST अनुरोध

POST का उपयोग सर्वर को डेटा भेजने के लिए किया जाता है। केवल डेटा का अनुरोध करने के बजाय, आप एक पेलोड सबमिट कर रहे हैं जिसे सर्वर प्रोसेस कर सकता है, स्टोर कर सकता है, या उस पर कार्य कर सकता है। यह हमारे शेड्यूलर के लिए आवश्यक है, जिसे क्लाइंट से शेड्यूल आइटम स्वीकार करने की ज़रूरत है।

चरण 5: POST एंडपॉइंट बनाना

अब आइए अपने सर्वर में एक POST एंडपॉइंट जोड़ें:

server.post('/upload/test', function(req, res, next) {
    console.log('Received POST request');
    console.log('Body:', req.body);
    res.send(200, { status: 'ok' });
    next();
});

कुछ महत्वपूर्ण बातों पर ध्यान दें:

  • पहला पैरामीटर एंडपॉइंट पथ है: /upload/test
  • दूसरा पैरामीटर एक कॉलबैक फ़ंक्शन है जो अनुरोध को संभालता है
  • req में आने वाले अनुरोध का डेटा होता है, जिसमें बॉडी भी शामिल है
  • res का उपयोग क्लाइंट को प्रतिक्रिया वापस भेजने के लिए किया जाता है
  • next() Restify में मिडलवेयर चेनिंग के लिए महत्वपूर्ण है

चरण 6: अपने POST एंडपॉइंट का परीक्षण करना

आप GET अनुरोधों की तरह अपने ब्राउज़र में POST अनुरोधों का परीक्षण नहीं कर सकते—आपको एक उचित HTTP क्लाइंट की आवश्यकता है। मैं Advanced REST Client की सिफारिश करता हूँ, जो एक Chrome एक्सटेंशन है और API का परीक्षण सरल व सहज बनाता है।

अपना अनुरोध सेट करना

  1. विधि को POST पर सेट करें
  2. अपना URL दर्ज करें: http://localhost:8080/upload/test
  3. Content-Type को application/json पर सेट करें
  4. बॉडी में अपना JSON पेलोड जोड़ें

महत्वपूर्ण: JSON सिंटैक्स मायने रखता है!

जब मैन्युअल रूप से JSON पेलोड तैयार करें, तो याद रखें कि JSON को स्ट्रिंग्स के लिए डबल कोट्स की आवश्यकता होती है, सिंगल कोट्स की नहीं:

{"test": "This is valid JSON"}

ऐसा नहीं:

{'test': 'This will cause errors'}

अनुरोध भेजने से पहले अपने JSON को मान्य करने के लिए JSONLint जैसे टूल्स का उपयोग करें।

चरण 7: अनुरोध डेटा पढ़ना और स्टोर करना

अब जब हम POST अनुरोध प्राप्त कर सकते हैं, तो आइए वास्तव में डेटा स्टोर करें।

इस ट्यूटोरियल के लिए, हम इन-मेमोरी स्टोरेज का उपयोग करेंगे (जो सर्वर के पुनरारंभ होने पर रीसेट हो जाएगा—हम अगले ट्यूटोरियल में MongoDB के साथ स्थायी स्टोरेज को कवर करेंगे)।

// अपना डेटा स्टोर करने के लिए एक वेरिएबल घोषित करें
var testData = [];

server.post('/upload/test', function(req, res, next) {
    // रिक्वेस्ट बॉडी से 'test' फ़ील्ड निकालें
    var scheduleItem = req.body.test;

    // इसे अपने ऐरे में जोड़ें
    testData.push(scheduleItem);

    console.log('Stored item:', scheduleItem);
    console.log('Total items:', testData.length);

    res.send(200, { status: 'ok', message: 'Item stored successfully' });
    next();
});

चरण 8: स्टोर किया गया डेटा प्राप्त करना

हमने डेटा स्टोर कर लिया है, लेकिन इसे कैसे प्राप्त करें? आइए अपना GET एंडपॉइंट अपडेट करें:

server.get('/test', function(req, res, next) {
    // स्टोर किए गए सभी आइटम्स की पूरी ऐरे लौटाएं
    res.send(testData);
    next();
});

अब आप यह कर सकते हैं:

  1. /upload/test पर कई आइटम POST करें
  2. सभी स्टोर किए गए आइटम्स प्राप्त करने के लिए /test को GET करें

सामान्य गलतियाँ और उनसे कैसे बचें

1. रिस्पॉन्स भेजना भूलना

यदि आप रिस्पॉन्स नहीं भेजते हैं, तो क्लाइंट अनिश्चित काल तक उसका इंतज़ार करते हुए लटका रहेगा। हमेशा अपने रिक्वेस्ट हैंडलर्स को res.send() के साथ समाप्त करें।

2. next() फ़ंक्शन को अनदेखा करना

Restify में, जब तक आपने पहले से रिस्पॉन्स नहीं भेजा है, हमेशा अपने हैंडलर्स के अंत में next() को कॉल करें। यह मिडलवेयर को प्रोसेसिंग जारी रखने की अनुमति देता है।

3. इनपुट को मान्य नहीं करना

प्रोसेस करने से पहले हमेशा आने वाले डेटा को मान्य करें। प्रोडक्शन में, आप यह जांचना चाहेंगे कि आवश्यक फ़ील्ड्स मौजूद हैं और सही प्रकार की हैं।

आगे क्या?

इस ट्यूटोरियल में, हमने यह कवर किया है:

  • Node.js इंस्टॉल करना और अपना वातावरण सेट करना
  • Restify और Express के बीच अंतर समझना
  • GET और POST एंडपॉइंट्स बनाना
  • Advanced REST Client के साथ APIs का परीक्षण
  • JSON payloads पढ़ना और डेटा स्टोर करना

लेकिन एक बड़ी सीमा यह है: सर्वर के पुनरारंभ होने पर हमारा डेटा गायब हो जाता है। अगले ट्यूटोरियल में, हम स्थायी स्टोरेज के लिए MongoDB को एकीकृत करेंगे। MongoDB एक NoSQL डेटाबेस है जो डेटा को JSON जैसे फ़ॉर्मेट में स्टोर करता है, जो इसे Node.js एप्लीकेशन्स के लिए एक स्वाभाविक विकल्प बनाता है।

उसके बाद, हम ऐसी क्लाइंट एप्लीकेशन्स बनाना शुरू करेंगे जो हमारे scheduler API से संवाद कर सकें, और पूरी सिस्टम को जीवंत बनाएंगे।

अंतिम विचार

REST API बनाना पहली बार में कठिन लग सकता है, लेकिन इसे छोटे, प्रबंधनीय चरणों में तोड़कर देखें तो यह पूरी तरह से संभव हो जाता है। अब आपके पास ऐसी APIs बनाने का बुनियादी ज्ञान है जो डेटा स्वीकार कर सकें, उसे प्रोसेस कर सकें, और क्लाइंट्स को वापस सर्व कर सकें।

याद रखें: सीखने का सबसे अच्छा तरीका है करके सीखना। कोड में बदलाव करें, विभिन्न एंडपॉइंट्स के साथ प्रयोग करें, और चीज़ों को बिगड़ने से न डरें—हम इसी तरह सीखते हैं!

अगले भाग में, हम MongoDB में गहराई से जाएंगे और सीखेंगे कि अपने डेटा को स्थायी कैसे बनाएं। तब तक, कोडिंग का आनंद लें!
