[02:00] एजेंट स्टैक रिलीज़ रीडआउट: Hermes Agent v0.22.2, v0.22.1, v0.22.0, v0.21.7

Hermes Agent v0.22.2 15 अक्टूबर, 2026 को शिप हुआ, और यही वह रिलीज़ है जो v0.22.1 होना चाहिए था। पिछले दिन, v0.22.1 गलत कमिट से बना था, जिसका मतलब है कि इसने अनरेलीज़्ड गेटवे वर्क शिप किया, और Microsoft Store वर्शन "Connecting" स्क्रीन पर अटक सकता है। 0.22.2 उस गलती को वापस लेता है और इसके बजाय दो फिक्स शिप करता है।

दोनों में से बड़ा है एक रिबूट बग। Linux पर, रीस्टार्ट के बाद, कर्नेल एक शुरुआती PID दे सकता है जो किसी पूरी तरह से असंबंधित प्रोसेस से संबंधित होती है जो पहले शुरू हुई। सुपरवाइज़्ड गेटवे - systemd, launchd, Docker - तब देखता कि एक रनिंग गेटवे जैसा दिख रहा है और शुरू होने से मना कर देता। Hermes अब रिकॉर्ड करता है कि उसने किस बूट में शुरू किया, और जब वह बता नहीं पाता, तो होस्ट लॉक से पूछता है, जिसे केवल एक लाइव गेटवे ही रखता है।

दूसरा लोकल मॉडल के लिए लैपटॉप एर्गोनॉमिक्स का एक स्वीप है। लोकल रिक्वेस्ट अब हमेशा स्टेटस लाइन पर प्रॉम्प्ट-रीडिंग प्रोग्रेस स्ट्रीम करती हैं, ताकि आप देख सकें कि लंबे प्रॉम्प्ट पर सर्वर कहां पहुंचा है। स्टॉल टाइमर उस समय को छोड़ देते हैं जब लैपटॉप सोया हुआ था, ताकि सोया हुआ कन्वर्सेशन स्टॉल न दिखे। एक रिकवर्ड लोकल सर्वर को सर्किट ब्रेकर की जगह एक अतिरिक्त रिट्राई मिलती है जो हर बाद के टर्न पर फेल होता है। कम्प्रेशन अब तब टाइमआउट नहीं होता जब सर्वर अभी भी एक लंबा कन्वर्सेशन पढ़ रहा हो। Windows यूनिफाइड-मेमोरी मशीनों पर, मॉडल लॉन्च और प्रॉम्प्ट कैश को फ्री मेमोरी के अनुसार साइज़ किया जाता है, जो तब मायने रखता है जब अलग VRAM पूल नहीं होता।

एक चेतावनी जो प्रोजेक्ट दे रहा है: वे सेशन जो 0.22.1 गेटवे के तहत चले थे, 0.22.2 में डिलीट नहीं किए जा सकते। जो कुछ भी सही बिल्ड के तहत साफ-सुथरे शुरू हुए थे उन्हें क्लियर किया जा सकता है; केवल बैड-बिल्ड सेशन ही फंसे हुए हैं।

लाइन के लिए संदर्भ: v0.22.0 13 अक्टूबर को "Threshold Release" के रूप में आया, जिसे प्रोजेक्ट ने विंडो के सबसे बड़े Hermes शिप के रूप में वर्णित किया, v0.21.0 साइकल की तुलना में लगभग 2.5x। वहां मुख्य एडिशन थे एक गाइडेड फर्स्ट-लॉन्च सेटअप चैट जो एक फ्री ट्रायल मॉडल पर चलता है ताकि नए लोगों को शुरू करने के लिए API की ज़रूरत न हो, कनेक्टर्स जो एजेंट को होस्टेड ऐप्स में लाते हैं, लोकल मॉडल के लिए वन-क्लिक llama.cpp रनटाइम, और साइन्ड डेस्कटॉप पैकेज जिसमें Microsoft Store बिल्ड शामिल है।

बिल्डर्स के लिए, यह मुख्य रूप से एक स्थिरता अपडेट है। अगर आपका सुपरवाइज़्ड गेटवे सर्वर रिबूट के बाद शुरू होने से मना कर रहा था, या आपका Store ऐप Connecting पर फ्रीज़ हो गया, तो यह अपडेट फिक्स है। लोकल-मॉडल टिंकरर्स, विशेषकर Windows यूनिफाइड-मेमोरी लैपटॉप पर, लंबे कन्वर्सेशन और लैपटॉप स्लीप पर एक शांतिपूर्ण अनुभव पाते हैं।

[04:38] Apple MLX, Mac Studio Cluster पर Near-Trillion Parameter Muse Spark Open चलाता है

Apple का ML research group ने frontier-scale language models को पूरी तरह Mac Studio hardware पर MLX का उपयोग करके चलाने के लिए एक hands-on guide प्रकाशित किया है, जो उनका open-source array framework है। मुख्य परिणाम: Muse Spark Open नामक एक near-trillion parameter mixture-of-experts model, M5 Ultra chips वाले चार Mac Studios में वितरित होने पर प्रति सेकंड 36 से अधिक tokens तैयार करता है, जो औसत reading speed से काफी ऊपर है।

512GB unified memory वाले एकल M5 Ultra Mac Studio पर, Mistral Medium 3.5 (128 billion parameters) और Qwen 3.8 (27 billion parameters) दोनों आराम से fit होते हैं। M5 generation एक GPU Neural Accelerator जोड़ता है जो matrix multiplication के लिए समर्पित है, जो M3 Ultra की तुलना में 4.6× तेज time-to-first-token में अनुवादित होता है। Decode speed, जो memory bandwidth से सीमित है, M5 Ultra के 1.2 TB/s unified memory bandwidth के कारण लगभग 1.6× बेहतर होती है, जो M3 Ultra पर 819 GB/s से बढ़ा है। Peak power लगभग 300 watts पर रहता है, जो लगभग एक toaster की खपत के बराबर है।

Muse Spark Open, जिसमें 816 billion कुल parameters और प्रति token 42 billion active हैं, NVFP4 quantization में लगभग 493GB की आवश्यकता होती है, जो एक मशीन के लिए बहुत बड़ा है। MLX v0.30.1 और बाद में, macOS 26.2 के low-latency RDMA-over-Thunderbolt 5 driver के साथ, jaccl कहलाने वाले नए communication collectives का उपयोग करके मॉडल को कई Macs में विभाजित करता है। MLX दो दृष्टिकोणों का समर्थन करता है: pipeline parallelism, जो model को depth में विभाजित करता है (एक Mac पहले आधे layers को चलाती है, फिर दूसरे को results पास करती है), और tensor parallelism, जो width में विभाजित करता है। एक helper command, mlx.launch, Thunderbolt-tied pair पर कई hosts में jobs fire करना आसान बनाता है।

[06:22] Open-source 3D architectural editor AI agents के लिए CLI और MCP tools जारी करता है

Pascal Editor repository, एक open-source 3D architectural editor, ने हाल ही में updates push किए जिसमें 13 October को इसके @pascal-app/cli package का version 1.0.4 शामिल है, repository खुद 16 October को फिर से push की गई। प्रोजेक्ट एक local command-line interface और Model Context Protocol tools प्रदान करता है, और इसे human designers और AI agents दोनों के लिए practical workflows का समर्थन करने के रूप में वर्णित किया गया है। MCP piece दिलचस्प हिस्सा है: MCP वह standard है जो AI assistants को external tools call करने की अनुमति देता है, इसलिए इसे एक 3D editor में integrate करने का मतलब है कि agent-driven workflows एक first-class concern हैं, bolted-on afterthought नहीं। Repo लगभग 24,900 GitHub stars पर है, जो सुझाव देता है कि इसके आसपास एक established builder audience पहले से बन चुकी है। developers के लिए, takeaway यह है कि CLI plus MCP tooling editor को day one से scriptable और agent-accessible बनाता है, useful if आप repetitive modeling tasks को automate करना चाहते हैं या design process के कुछ हिस्सों को एक AI assistant को सौंपना चाहते हैं बिना direct human workflow को छोड़े। 16 October का push active maintenance दिखाता है। उस documentation पर नज़र रखें कि कौन से specific MCP tools ship होते हैं और वे कौन से scene operations expose करते हैं, क्योंकि वह list तय करेगी कि एक agent अपने आप editor का कितना हिस्सा realistically drive कर सकता है।

[07:37] MiniCPM-V 4.7 को Speculative Decoding के माध्यम से Speed Boost मिलती है

OpenBMB ने Hugging Face पर MiniCPM-V 4.7 के लिए GGUF-quantized DSpark draft checkpoint प्रकाशित किया, जो llama.cpp के साथ speculative decoding को सक्षम करता है। MiniCPM-V एक ओपन vision-language मॉडल परिवार है जो on-device और edge deployment के लिए डिज़ाइन किया गया है, और यह repository इसे llama.cpp speculative decoding के साथ runnable बनाती है। Speculative decoding एक छोटे draft मॉडल को जोड़ती है जो कई tokens की भविष्यवाणी करता है, एक बड़े target मॉडल के साथ जो उन भविष्यवाणियों को समानांतर में सत्यापित करता है। 35-billion-parameter मॉडल को एक समय में एक token generate करने की प्रतीक्षा करने के बजाय, draft एक batch प्रस्तावित करता है जिसे target पुष्टि या अस्वीकार करता है, जो दृश्यमान output rate को गति देता है। Draft में लगभग 389 मिलियन पैरामीटर हैं और प्रति forward pass 15 tokens की भविष्यवाणी करता है, base मॉडल में specific hidden-state layers को लक्षित करता है। Evaluation numbers दिखाती हैं कि general text पर प्रति verification round लगभग 3.5 tokens से लेकर code tasks पर 7.4 तक acceptance lengths हैं, MMMU और MathVista जैसे vision benchmarks में लगभग 5 से 6 tokens accepted होते हैं। इसका उपयोग करने के लिए, target मॉडल, इसका vision projector, और quantized draft download करें, फिर llama-cli में draft-dspark spec type के साथ चलाएं या इसे एक multimodal server के रूप में launch करें। Draft को matching MiniCPM-V 4.7 35B-A3B target के साथ जोड़ा जाना चाहिए, और इसके लिए एक llama.cpp build की आवश्यकता है जो dflash architecture और DSpark Markov head का समर्थन करता हो। Draft को खुद quantize करने से केवल यह प्रभावित होता है कि भविष्यवाणियां कितनी बार स्वीकृत होती हैं, कभी भी final output नहीं, इसलिए developers अपनी memory budget के अनुरूप सबसे छोटा quantized draft उपयोग कर सकते हैं। Draft मॉडल प्रति forward pass 15 tokens की भविष्यवाणी करता है, और benchmarks दिखाते हैं कि publisher-reported averages general text पर प्रति verification step 3.501 accepted tokens और code generation पर 7.387 हैं। Quantized draft llama-cli या llama-server के साथ --spec-type draft-dspark flag का उपयोग करके चलता है, जिसके लिए dflash architecture वाली llama.cpp build की आवश्यकता है।

[09:24] NVIDIA Nemotron Family को Super VL और Bolt Edge Models के साथ विस्तारित किया

NVIDIA ने इस सप्ताह अपने ओपन Nemotron परिवार को तीन मॉडलों के साथ विस्तारित किया जो संपूर्ण agent deployment range को कवर करते हैं — data center से लेकर RTX desktops तक। फ्लैगशिप Nemotron 3.5 Super VL है, एक 120-billion-parameter ओपन मॉडल जो high-volume always-on agents के लिए Nemotron Coalition के साथ बनाया गया है। NVIDIA कहता है कि यह लगभग one-fifth parameter count पर अपने सबसे बड़े reasoning मॉडल की accuracy से मेल खाता है, और Artificial Analysis Intelligence Index पर अपनी class में अगले सर्वश्रेष्ठ की तुलना में 5x तेज चलता है।

Bolt 74B-A9B 24GB RTX और DGX Spark पर local agentic workloads के लिए बनाया गया है। ट्रिक एक native 2-bit quantization है — एक compression जो 74-billion-parameter मॉडल को 24GB memory में समाता है, जिससे अन्य applications के लिए जगह बचती है। NVIDIA इसे PinchBench पर अपनी memory class में #1 open model और BrowseComp पर #2 के रूप में रैंक करता है। यह llama.cpp, Ollama, LM Studio, Unsloth, और vLLM का समर्थन करता है।

तीसरा मॉडल, Bolt E4B 4GB, GeForce RTX, Jetson, और DGX Spark पर conversational और physical agents के लिए 23 अक्टूबर को आता है। Super VL और Bolt 74B-A9B अभी Hugging Face, Open Router, ModelScope, और NVIDIA NIM microservices पर उपलब्ध हैं।

Super VL को लगभग 26 trillion tokens पर train किया गया था और दर्जनों reinforcement-learning environments में लगभग 3.8 मिलियन samples के साथ post-train किया गया। NVIDIA Hugging Face पर tool use, finance, instruction following, long context, fairness, और vision-language understanding के लिए open datasets भी जारी कर रहा है, साथ ही NeMo Gym में reinforcement-learning environments भी।

GitHub ने 15 अक्टूबर को एक changelog पोस्ट किया जिसमें घोषणा की गई कि GitHub Copilot models का एक सेट 16 नवंबर, 2026 को बंद कर दिया जाएगा। depreciation हर Copilot surface पर लागू होता है: Copilot Chat, inline edits, ask mode, agent mode, और code completions। व्यावहारिक प्रभाव यह है कि कोई भी उपयोगकर्ता जिसने अपनी Copilot सेटिंग्स में जल्द ही बंद होने वाला model pin किया है, उसे cutoff date पर काम करना बंद हो जाएगा। Code completion, chat, और agent runs जो प्रभावित models में से किसी एक पर निर्भर थे, उस दिन के बाद एक नए default की आवश्यकता होगी। प्रभावित models की पूरी सूची GitHub changelog पोस्ट में है, साथ ही सुझाए गए प्रतिस्थापन भी। depreciation एक ही दिन Copilot Chat, ask mode, agent mode, inline edits, और code completions पर प्रभाव डालती है, इसलिए एक Copilot उपयोगकर्ता जो एक सत्र के मध्य में inline completion से chat में स्विच करता है, सतहों को बदलकर खुद को नहीं बचाएगा। कोई भी जिसकी टीम ने एक Copilot plan के पीछे एक विशेष model पर मानकीकृत किया है, यह पुष्टि करना चाहेगा कि वह विकल्प अभी भी समर्थित सूची में है।
